# Module Learning Pages

Clicking an unlocked card on the Modules screen opens a dedicated learning page
for that module. The page is fully **content-driven**: everything it shows is
described by a plain-data content file, so adding a new module requires no new
components.

The reference implementation is **String Indexing**
(`frontend/src/data/moduleContent/indexing.js`).

## Page anatomy

Every module page has the same four sections, navigated by the sticky
zero-indexed rail on the left:

| # | Section   | Driven by                | Renders with                                  |
|---|-----------|--------------------------|-----------------------------------------------|
| 0 | Learn     | `learnSections[]`        | `components/module/ContentBlocks.jsx`         |
| 1 | Examples  | `examples[]`             | `components/module/WorkedExample.jsx`         |
| 2 | Visualize | `visualizer`             | `components/module/visualizers/` (by `type`)  |
| 3 | Practice  | `practice`               | `components/module/PracticeSection.jsx`       |

Practice questions come from the real backend pipeline:
`GET /api/exercises/<module_id>` for the questions and
`POST /api/exercises/submit` for misconception-aware grading. Code-writing
questions embed an editor that runs through `POST /api/execute` and can show a
step trace from `POST /api/debug` ("Visualize code").

## Adding a new module (checklist)

1. **Create the content file** `frontend/src/data/moduleContent/<id>.js`,
   copying the shape of `indexing.js`. `<id>` must match the backend module id
   in `backend/app/data/exercises.json` (e.g. `slicing`).
2. **Register it** in `frontend/src/data/moduleContent/index.js`:
   ```js
   import { slicingModule } from './slicing';
   export const MODULE_CONTENT = {
     [indexingModule.id]: indexingModule,
     [slicingModule.id]: slicingModule,
   };
   ```
3. **Check `frontend/src/data/modules.js`** has a card with the same `id`
   (all eight already do).
4. **(Optional) Add a visualizer.** Create a component in
   `frontend/src/components/module/visualizers/` and register it in that
   folder's `index.js`. Point the content file at it with
   `visualizer: { type: '<your-type>', ... }`. Reusing the `indexing` type is
   fine while a dedicated one doesn't exist yet.

Modules without a registered content file show a friendly "still being
written" screen instead of breaking.

## Learn block reference

```js
{ kind: 'p',         text }                          // paragraph; `code` and **bold** supported
{ kind: 'code',      code, caption? }                // syntax-highlighted Python
{ kind: 'string',    value, highlight?, negative? }  // indexed string-cell figure
{ kind: 'callout',   tone, title, text }             // tone: tip | warn | info | define
{ kind: 'keypoints', title?, items: [] }             // summary card
{ kind: 'table',     head: [], rows: [[]] }          // comparison table
```

## Worked example reference

```js
{
  id, title, intro,
  string: 'robot',            // figure shown above the steps
  code: '...',                // full snippet
  steps: [
    {
      text: '...',            // reasoning for this step (`code` spans allowed)
      highlight: [2],         // cells to light up in the figure
      state: 'mid = 2',       // optional state chip
      output: 'b',            // optional terminal output line
      error: true,            // optional: style the step as an error
    },
  ],
}
```

## Styling

All page styles live in `frontend/src/styles/ModulePage.module.css` and consume
the global design tokens from `App.module.css`, so new modules automatically
match the existing look. The stylesheet is responsive down to mobile and
respects `prefers-reduced-motion`.

## Exam mode & the expanded question bank (July 2026)

### New exercise fields
The bank (`backend/app/data/exercises.json`) now supports, per question:

- `explanation` — teaching text returned by `/api/exercises/submit` with every
  grading result (right or wrong) and shown in practice feedback and exam review.
- `starter_code` — initial editor content for `write_code` questions; used for
  debug-the-code questions where students fix broken code.
- `stars` — the question's star value (the legacy `xp` field remains as
  `stars * 10` for API compatibility; the UI speaks only in stars).
- `tags` — e.g. `exam_style`, `trap`, `conceptual`, `debug`.

New exam-style questions are generated by `generate_exam_questions.py`, which
**executes every predict-the-output answer before writing it** — answers in the
bank are machine-verified.

### Exam mode
A module opts in with `practice.exam = { questionCount: N }` in its content
file. `PracticeSection` then renders a Practice | Exam tab switcher:

- **Practice** — the original one-at-a-time runner with instant feedback.
- **Exam** (`components/module/ExamMode.jsx`) — draws N random questions,
  free navigation via a numbered palette, one submission for the whole paper
  (with an unanswered-questions confirmation), then a results screen: score,
  percentage, stars earned, a 0-3 star mastery band with badge
  (Mastered / Proficient / Developing / Keep practising), per-question review
  with the student's answer, the correct answer and the explanation, and
  "areas for improvement" grouped by misconception. Retry redraws the paper.

### Visualizers
`visualizer: null` in a content file omits the Visualize section entirely
(rail indices shift automatically). A second visualizer type is registered:
`slicing` — an animated start/stop/step slice machine implementing Python's
exact semantics, including negative-step defaults.
